# Example files for manual testing of the «Обработка» page

Three sets, one per scenario from the technical specification.
All files are synthetic and ready to be uploaded through the UI.
Real client files from the specification live in `Task1/` and `Task2/` —
they are reference material; for live demos use the synthetic sets below
(real PDFs parse poorly and `.docx` price lists are rejected by upload).

## Folder layout

```
examples/
├── leader_smi/
│   ├── 01_prices_leader_smi.xlsx     # upload as «positions»

├── veneta/

├── dlux/

    ├── payment_registry_synthetic.xlsx   # upload as «payment_registry»
    └── contract_registry_synthetic.xlsx  # upload as «contract_registry»
```

## How to test (per scenario)

1. **Upload** оба файла из папки сценария на странице «Загрузка»
   (тип файла подставляется автоматически по имени, проверьте селекты).
2. Перейти на страницу **«Обработка»**.
3. В выпадающих списках выбрать загруженные файлы (последние выбираются сами).
4. Сценарий: «Автоопределение» или явный («Лидер СМИ» / «Венета» / «Д-люкс»).
5. Чекбокс **«LLM-верификация спорных позиций»** для демо держите выключенным:
   обработка занимает секунды; с LLM на CPU — минуты (каждая спорная строка
   ждёт ответа Ollama).
6. Нажать **«Обработать»**: таблица совпадений + скачивание XLSX (колонки A–G).

## What is inside each set

### 1. `leader_smi/` — simple UPD

**Прайс**: 50 рекламных услуг (ТВ, радио, пресса, интернет, наружная реклама, производство).
**УПД**: 25 строк с сокращёнными формулировками («Видеоролик на ТК Россия 1» и т.п.).

Expected: все 25 строк матчатся на правильные позиции (валидация — 100%).
Часть строк попадает в зону уверенности 50–85% и помечается «на проверку» —
это штатное поведение порогового правила, а не ошибка.

### 2. `veneta/` — simple UPD

**Прайс**: 50 картриджей и расходников.
**УПД**: 25 строк.

Expected: точность сопоставления на эталоне — 96%; цена F = сумма/количество.

### 3. `dlux/` — complex act

**Прайс**: 30 услуг автомойки, разбитых секциями СЕДАН / ДЖИП / МИКРОАВТОБУС.
**Акт**: 18 строк, в том числе составные («мойка и полировка» → две строки результата),
строки с «сильным загрязнением» и марки автомобилей вместо категорий.

Expected:
- скидка 15% от прайса: F = цена_прайса × 0.85;
- коэффициент 1.5 при «сильном загрязнении» (жёлтая подсветка + пояснение);
- категория определяется по марке (Camry → седан, RAV4 → джип, Sprinter → микроавтобус);
- строки с марками вне словаря (например, Tesla/BYD) намеренно остаются
  с пометкой «Категория автомобиля не распознана» — это контролируемая деградация;
- точность на эталоне — 88.9%, все расхождения помечены needs_review.

### 4. `Task2/synthetic/` — registries for the SMSP flow

138 платежей + 65 договоров → первичный свод ~70 строк (5 без сопоставления
с реестром договоров — специально), итоговый свод с долями СМСП по сумме
и по количеству. Используйте страницу «Свод СМСП»; правки таблицы шага 2
автоматически сохраняются при переходе к итоговому своду.

## Optional form fields («Обработка»)

- Номер документа и дата — если пусто, бэкенд достаёт их из файла регексом
  («Счет-фактура №», даты `dd.mm.yyyy` — берётся самая поздняя).
- Номер договора, ИНН и комментарий сохраняются в метаданные задачи.

## «Сценарий обработки» field

Сценарий **влияет на обработку**: «Д-люкс» включает логику акта (скидка,
коэффициент, категории, разбиение строк), «Лидер СМИ»/«Венета» — стандартную
логику УПД. При противоречии сценария и типа файла (например, «Д-люкс» + УПД)
все строки помечаются «Сценарий не соответствует типу файла».

## Regenerating the examples

```bash
python examples/_generate_examples.py          # leader_smi / veneta / dlux
python examples/Task2/synthetic/generate.py    # реестры Задачи 2
```
